# Design brief — Gridfinity Generator

Бриф для Claude Design. Источник функциональности: `openspec/changes/01…09` (см. `openspec/ROADMAP.md`).

## 1. Продукт

Клиентский (без бэкенда) параметрический генератор деталей **Gridfinity** для 3D-печати. Три режима:

- **Box** — контейнер/лоток на сетке Gridfinity.
- **Baseplate** — базовая пластина под ящики.
- **Cutout** — ящик с вырезом под инструмент (по STL-модели или простой фигуре).

Пользователь меняет параметры слева и сразу видит 3D-превью справа. Результат экспортируется в **STL** и **3MF** (с пресетами Bambu Studio).

**Аудитория:** владелец 3D-принтера, разбирающийся в допусках и миллиметрах, но не в CAD. Пришёл решить задачу: «ящик под мои размеры, который напечатается на моём столе».

**Тон:** инструмент, а не маркетинг. Плотный, спокойный, быстрый. Никаких лендингов, hero-блоков и иллюстраций.

**Референсы (структура, не копирование):**
- gridfinitygenerator.com — три режима и состав параметров.
- pandagao.github.io/gridfinity-studio — экспорт 3MF и пресеты Bambu.

## 2. Ограничения

- Стек: React + Tailwind CSS v4 (токены как CSS-переменные в одном `theme.css`), иконки **Tabler Icons**. Дизайн должен раскладываться на эти токены и иконки.
- **Только тёмная тема** на первом этапе (3D-вьюпорт тёмный, остальное под него).
- **Две локали: en и ru.** Русские подписи длиннее на 20–40%; макеты должны это выдерживать, без обрезки и без переноса ломающего сетку. Показать оба языка хотя бы на одном экране.
- **Единицы mm/inch**: глобальный переключатель; каждое числовое поле показывает единицу рядом со значением. Внутри всё в мм, дюймы только отображение (3 знака после запятой).
- Приоритет — **десктоп** (≥1280 px). Планшет/мобильный — отдельным кадром: панель параметров становится выдвижной шторкой над вьюпортом.
- Цвета не должны быть единственным носителем смысла (ошибки, предупреждения дублируются иконкой и текстом).
- Размеры целей клика ≥ 32 px, видимый фокус, работа с клавиатуры.

## 3. Раскладка приложения

```
┌─────────────────────────────────────────────────────────────┐
│ Лого   [ Box | Baseplate | Cutout ]       mm/in   EN/RU     │  шапка
├───────────────────┬─────────────────────────────────────────┤
│ Панель параметров │                                         │
│ (секции-аккордеон,│            3D-вьюпорт                   │
│  скролл)          │   (+ плавающие кнопки: вид, сброс       │
│                   │    камеры, габариты, сетка)             │
│                   │                                         │
├───────────────────┤                                         │
│ Экспорт (липкий   │   нижняя строка: габариты XYZ, объём    │
│ блок внизу)       │                                         │
└───────────────────┴─────────────────────────────────────────┘
```

- Ширина панели ~360–400 px, фиксированная; вьюпорт занимает остальное.
- Секции панели сворачиваются, состояние запоминается. В свёрнутом виде секция показывает краткую сводку («3 × 2, магниты: углы»).
- Блок экспорта всегда виден внизу панели.

## 4. Общие компоненты (показать на отдельной странице-библиотеке)

- **LengthField** — числовое поле с единицей справа, шагами ± и стрелками клавиатуры; принимает дроби в дюймах (`1 1/2`). Состояния: default, focus, error, disabled.
- **Сегментированный переключатель** (режим крепежа none/corner/full/manual, лип-стиль, единицы).
- **Слайдер + поле** для толщин.
- **Секция-аккордеон** с заголовком, сводкой, кнопкой «сбросить секцию».
- **Бейдж/баннер** предупреждения и ошибки (не помещается на стол, невалидная модель, неверный STL).
- **Пустое состояние** и **индикатор расчёта** (геометрия считается в воркере: показывать прогресс, не блокируя ввод).
- Тултипы с пояснением параметров (особенно для ledge, scoop, clearance).

## 5. Экраны и состояния

### 5.0 Стартовая страница
Корневой экран приложения без вьюпорта и панели параметров. По центру три крупные карточки **Box | Baseplate | Cutout**: иконка (Tabler) или схематичная иллюстрация детали, название, одна строка описания, вся карточка кликабельна. Сверху минимальная шапка: логотип, язык, mm/inch. Состояния: hover/focus карточек, русская локаль. Без маркетинга и героя: это экран выбора инструмента, он занимает один экран без прокрутки. Логотип в шапке любого режима возвращает сюда, параметры режимов сохраняются.

### 5.1 Оболочка
Шапка, переключатель режимов, язык, единицы. Первый запуск (определён язык браузера), состояние загрузки WASM, ошибка загрузки.

### 5.2 Baseplate
- Размер: ячейки X×Y **или** произвольные размеры мм. **Дробные xy-юниты** (ящики редко кратны 42): выбор выравнивания остатка (padding слева/справа/по центру), подсветка отступов на превью.
- Толщины: основание, стенки, зазор.
- Крепёж — см. 5.5.
- **Разделение на части** под ограничение печатного стола: размер стола (пресет принтера или ввод), автоматическое разбиение, ручные позиции разрезов; превью частей с подписями (A1, A2…) и цветами; раскладка на столе.
- **Соединители** (торцевые отверстия/пазы): тип, размеры, допуск; предупреждение, если соединитель ломает деталь.

### 5.3 Box / Tray
- Размер: ячейки + высота в юнитах (7 мм), **дробные xy** с «подогнать под содержимое».
- Стенки и пол, **толщины**.
- **Lip** (стиль стыковки сверху), **ledge** (уступ под вторую деталь/крышку; подсказка зачем нужен).
- **Scoop** (скругление дна для вынимания мелочи): радиус/вкл-выкл по сторонам.
- **Compartments** (перегородки): сетка, редактирование на 2D-схеме.
- Крепёж на дне — 5.5.

### 5.4 Cutout
- **Импорт STL** (drag-and-drop зона, выбор единиц и ориентации, ошибки «плохая сетка»).
- **Примитивы** без импорта: прямоугольник, круг/скруглённый прямоугольник.
- **Список вырезов** (несколько на ящик), у каждого: видимость, удалить, дублировать.
- **Размещение:** 2D-вид сверху с перетаскиванием, привязка к сетке и центрированию, выравнивание по осям, подсветка выхода за границы и пересечений.
- Глубина и зазор вокруг модели; режим вырезания (насквозь/на глубину).
- Измерения импортированной модели (габариты).

### 5.5 Крепёж (общий для Baseplate и Box)
- Винты и магниты: размеры и пресеты (например 6×2 мм магнит).
- Режимы размещения: **нет / по углам / в каждой ячейке / вручную**.
- **2D-редактор размещения:** ячейки сверху, точки привязки, клик — поставить/убрать, drag — переместить, список координат, удаление. Переход из «в каждой ячейке» в «вручную» превращает точки в редактируемые.

### 5.6 Экспорт
- Формат: STL / 3MF.
- **Пресеты принтеров Bambu** (выбор модели → объём стола), тип/цвет пластика не обязателен.
- **Превью печатного стола:** деталь(и) на плите с границей области печати и запасом по краю.
- Для разделённых пластин: экспорт всех частей одним 3MF или по файлам.
- Состояния: идёт сборка, готово, ошибка, не влезает на стол.

## 6. Что нужно получить от дизайна

1. Токены: цвета (фон, поверхности, границы, акцент, success/warn/error), типографика (шрифт, размеры, line-height), радиусы, отступы, тени. В виде, который переносится в Tailwind-тему.
2. Страница с библиотекой компонентов из раздела 4 со всеми состояниями.
3. Макеты десктоп-экранов: стартовая страница, Baseplate (в т.ч. с разделением), Box, Cutout (с импортом и размещением), Export. Для каждого основное и пустое состояние, ошибка/предупреждение.
4. Один экран в русской локали с самыми длинными подписями.
5. Мобильный/планшетный кадр с выдвижной панелью.
6. Вариант оформления вьюпорта: цвета модели, сетки, выделения, подписей частей, контрастность на тёмном фоне.

## 7. Чего не делать

- Не рисовать лендинг (стартовая страница это только выбор режима), онбординг-туры, маркетинговые блоки, аватары, аккаунты и логин.
- Не вводить светлую тему и не плодить акцентные цвета: один акцент и семантические цвета статусов.
- Не прятать основные параметры в модальные окна: параметры живут в боковой панели.
- Не использовать декоративные иллюстрации вместо 3D-превью.

## 8. Как результат попадает в проект

Утверждённый дизайн (ссылка/экспорт) кладётся в `design/`. В `01-app-foundation` добавить задачу «свести токены из утверждённого дизайна в Tailwind-тему (`theme.css`)».
